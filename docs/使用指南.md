# 原版使用指南

适用于蛙蛙创作工作室 4.8.0。返回 [项目首页](../README.md)。

## AI 与平台账号

在设置中分别配置写作、投稿文本和图像服务。接口地址、模型名称与密钥需要对应同一服务商支持的调用方式。相同请求次数不代表相同费用：输入长度、输出长度、使用的模型、失败重试和服务商计费方式都会影响成本。

先使用接口测试，再从少量任务开始运行。不要仅根据电脑核心数量把并行数调到最高；AI 限流、网络、浏览器操作和本地读写都会影响处理速度。

平台登录在“设置 → 平台账号”完成：

1. 添加账号并填写手机号，可设置备注。
2. 点击打开浏览器，手动完成登录。
3. 返回软件保存登录状态。
4. 在笔名库中配置该账号可用的笔名。

每个账号独立保存会话。登录过期时，到设置重新登录并保存。后台不会依靠弹出隐藏浏览器等待你完成登录。

## 写作与书库

创作工作台支持选择脑洞风格、生成企划并编辑内容，再加入写作任务。写作参数中的精写章节数与全书精写开关用于后续生成。

生产记录中查看当前步骤、章节进度和字数，可批量继续、暂停、收尾或删除。暂停中的任务可能需要先保存当前步骤，不要在保存过程中反复操作。

完稿自动进入作品书库。关闭“完稿自动投稿”后，书稿仍保留，可以稍后手动投稿或导出。未完稿在写作任务中阅读。

## 导入与投稿

已有书稿可在自动投稿中心导入并选择包装方案。系统按流程进行稿件检查、内容分析、分类标签匹配、书名与简介生成、封面生成、上传及提交。

从书库点击投稿会直接启动所选作品；无需为同一动作再到投稿中心点击一次。其他已暂停作品不会因此全部启动。

投稿包装可设置并行 1—6 本；平台浏览器写入仍串行处理。不要将“并行包装”理解为多个账号同时操作网页。

重投设置按质量、非质量和原因不明分别配置；0 表示不自动重投。重投请求仍占用该账号当日额度。

## 提示词怎么生效

在“设置 → 提示词设置”编辑对应环节。

| 操作 | 作用 |
| --- | --- |
| 保存本项 | 用于后续对应请求，不重做已有缓存结果 |
| 保存并更新待投稿作品 | 对未上传且不在执行中的任务重做相关步骤，跳过不适用任务 |
| 查看最近调用 | 查看该项最近使用的文本与时间 |
| 恢复默认后保存 | 用默认内容替换该项自定义内容 |

写作提示词修改不会重写已经保存的章节。续写、拒稿修订等提示词只有触发对应条件才会调用。“尚未调用”不一定表示失效。

自定义提示词应保留所需变量及 JSON 输出结构，避免一边要求纯文本、一边要求程序解析 JSON。

## 封面配置

封面只使用三项：

- **基础提示词**：书名、笔名、剧情信息和整体封面要求。
- **画风提取**：文本 AI 结合作品内容提取画风。
- **自定义附加**：直接追加到最终图像提示词。

旧的剧情视觉补充、独立构图、明暗、前缀及负面词设置不再作为独立项参与生成。查看封面相关项的最近调用时，可核对最终图像提示词。

书名与笔名由绘图模型画出，提示词不能保证文字百分之百准确。已经上传的作品不会因修改本地提示词自动更换封面；符合条件的本地包装可使用“按新规则重做封面”。

## 常见问题

### 额度已满，但今天没投稿成功

额度统计的是正式请求次数，不是成功作品数。失败、超时、重投和补交章节请求都可能占用额度。删除记录和重新登录不会退还次数。

按北京时间零点进入新一天，运行中的软件会检查等待任务。暂停或关闭状态不会替你继续任务，启动恢复行为还取决于设置。

### 删除投稿记录后，会不会把平台作品删掉？

不会。删除本地记录与删除平台作品是不同操作。投稿事实、笔名和正文仍用于判断书库状态；有远端信息的记录可以恢复。结果不明的任务先核对，不要重新导入来“重投一次”。

### 写完后找不到书

先查看作品书库，而不是只看生产记录。完稿与未完稿分开展示。关闭完稿自动投稿不会删除已完成作品。还可检查搜索与筛选条件。

### 书名没有达到 80 分

原名不足 80 分时，最多生成两次新候选。全部低于 80 分时选最高分的合法、未重名书名；若所有候选均为空、超长或同名，仍需调整。评分是模型评估，不代表真实平台推荐结果。

### 提示“文本 AI 未返回合法 JSON”

先查看失败环节和最近调用，检查自定义提示词是否保留格式要求，再确认接口和模型可正常响应。保存修正后重试当前步骤，不必重新导入整本书。不要把报错文本或不完整输出当作有效分析结果。

### 类目或标签不在平台库内

4.8.0 会对库外类目按对应大类尝试归入脑洞分类，标签从系统库中匹配。如果仍异常，保留错误内容并检查平台类目是否发生变化。不要通过自定义提示词强行提交不存在的名称。

### 多本并行时界面卡顿

先降低写作与投稿包装并行，减少同时处理的大稿件。更多 CPU 或内存不能保证解决界面刷新、文件读写或浏览器操作造成的卡顿。反馈时说明并行本数、书稿规模、卡顿页面和是否正在上传，便于区分瓶颈。

### 如何回到之前版本？

先退出软件并备份整个用户数据目录，再下载对应版本安装包。旧版不一定能读取新版写入的数据；如有升级前的数据备份，优先成套恢复，并核对备份之后发生的远端投稿和当日额度。详见 [版本回档](../版本回档.md)。
